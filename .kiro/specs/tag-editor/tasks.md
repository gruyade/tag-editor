# Implementation Plan: TagEditor

## Overview

Rust + Tauri による軽量デスクトップアプリの実装計画。純粋ロジック（拡張子判定・クランプ・booru変換・信頼度parse/render・集計・フィルタ・命名規則・連番・振分決定・パス変換・batch分割）を先に確立し、その上にファイルI/Oを伴うサービス、推論・モデル層、Tauri コマンド境界、UI の順で積み上げる増分方式。各タスクは前タスクの成果物を土台とし、宙に浮くコードを残さない。

テスト方針: 各 Correctness Property（26件）は `proptest` による単一プロパティテスト（最低100反復）として実装し、対応する設計プロパティ番号をコメント参照する。純粋ロジックはそのまま、対保存・書込ラウンドトリップは一時ディレクトリ、推論はモックセッションで検証する。`*` 付きサブタスクはオプション。

## Notes

- `*` 付きサブタスクはオプション（テスト）で、より速いMVPのためにスキップ可能。ただし各 Correctness Property の検証は本アプリの正しさ保証の中核であり、実装完了前に有効化を推奨。
- 各タスクはトレーサビリティのため具体的な要件番号を参照する。
- Checkpoint は増分的な検証点。
- プロパティテストは普遍的な正しさ性質（Property 1〜26）を検証し、単体テストは具体例・境界・異常系（UI分岐・部分失敗継続・原子性・衝突保持・破損継続・モデル異常系・symlink異常系・起動/応答性）を検証する。
- 純粋ロジック（タスク2〜8）を先に確立してから I/O・推論・コマンド・UI を積み上げることで、宙に浮くコードを残さず増分的に統合する。
- Property 13 は改名系（タスク13.2）と移動/コピー系（タスク14.2）で対保存を検証するため2箇所に配置する。
